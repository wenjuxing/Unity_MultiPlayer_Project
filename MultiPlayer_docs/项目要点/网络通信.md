## 模块二：网络通信

### 问题一：MessageRouter 的消息订阅与分发机制是怎样的？

**这是一个生产者-消费者模式的多线程消息分发器**，客户端和服务端代码几乎相同（同源 Summer 框架）。

```csharp
// === 生产端（IO 线程）===
// Connection 收到完整包 → 反序列化 → 加入队列
public void AddMessage(Connection sender, IMessage message)
{
    lock (messageQueue)
    {
        messageQueue.Enqueue(new Msg() { sender = sender, message = message });
    }
    threadEvent.Set(); // 唤醒1个worker线程
}

// === 消费端（Worker 线程）===
private void MessageWork(object state)
{
    while (_running)
    {
        if (messageQueue.Count == 0)
        {
            threadEvent.WaitOne(); // 阻塞等待唤醒
            continue;
        }
        Msg msg = null;
        lock (messageQueue) { msg = messageQueue.Dequeue(); }
        // 反射调用 Fire<T>，并递归处理嵌套子消息
        executeMessage(msg.sender, msg.message);
    }
}

// === 订阅 ===
public void Subscribe<T>(MessageHandler<T> handler) where T : IMessage
{
    string type = typeof(T).FullName;    // 用完整类型名当 key
    delegateMap[type] = (MessageHandler<T>)delegateMap[type] + handler;  // 委托链
}

// === 触发 ===
private void Fire<T>(Connection sender, T msg)
{
    string type = typeof(T).FullName;
    if (delegateMap.ContainsKey(type))
        (delegateMap[type] as MessageHandler<T>)?.Invoke(sender, msg);
}
```

**架构图**：

```
IO Thread (接收)                     Worker Pool (处理)
     │                                    │
     ├─ Socket.ReadAsync ─┐               │
     │                    │               │
     ├─ 粘包/半包处理      │               │
     │                    │               │
     ├─ 反序列化 Protobuf  │               │
     │                    ▼               │
     │           messageQueue (lock)      │
     │                    │               │
     └─ AddMessage() ─────┤               │
                          │   AutoResetEvent.Set()
                          ▼               │
                    threadEvent ──────────┼──► MessageWork()
                                          │       │
                                          │       ├─ Dequeue (lock)
                                          │       │
                                          │       ├─ executeMessage()
                                          │       │   ├─ Fire<T> (订阅者)
                                          │       │   └─ 递归遍历子消息
                                          │       │
                                          │       └─ WaitOne() (队列空时阻塞)
```

**递归消息处理的特殊设计**：

```csharp
private void executeMessage(Connection sender, IMessage message)
{
    // 1. 触发当前消息类型的订阅者
    Fire(sender, message);

    // 2. 遍历所有属性，递归处理嵌套的 IMessage 子消息
    foreach (var p in message.GetType().GetProperties())
    {
        if ("Parser" == p.Name || "Descriptor" == p.Name) continue;
        var value = p.GetValue(message);
        if (value is IMessage nested)
            executeMessage(sender, nested); // 递归
    }
}
```

这意味着一个包含嵌套消息的 Proto 消息会被**逐层展开触发**。例如 `InventoryResponse` 如果包含 `ItemInfo` 子对象，订阅 `ItemInfo` 的处理器也会被触发。

**关键特性总结**：

| 特性 | 实现 |
|------|------|
| **线程安全** | `lock (messageQueue)` + `ConcurrentQueue`（服务端） |
| **消费者唤醒** | `AutoResetEvent` — 队列空时阻塞，有消息时 `Set()` 唤醒 |
| **订阅/退订** | 委托链的 `+=` / `-=`，key 为 `typeof(T).FullName` |
| **递归分发** | 反射遍历属性，对每个 `IMessage` 子对象递归 `Fire` |
| **Worker 数** | 服务端 10 线程，客户端理论上单线程 |

### 问题二：TCP 粘包/半包问题如何解决？

**长度前缀帧协议**（`Connection.cs` / `SocketReceiver.cs`）：

```
┌──────────────────┬──────────────────────────┐
│  4 Bytes (int)   │   N Bytes (Protobuf)      │
│   Body Length    │   Serialized Message      │
│  (Little Endian) │                          │
└──────────────────┴──────────────────────────┘
```

流程：
1. **先读 4 字节** → 得到包体长度 `N`
2. **再读 N 字节** → 得到完整 Protobuf 数据
3. **反序列化** → `IMessage` 对象
4. **加入 MessageRouter 队列**

如果收到的数据不够 4 字节（半包头）或不够 N 字节（半包体），就**缓存并继续接收**，直到凑够完整包。
